ACTIVE V2 NATIVE MTP CANDIDATE -- independent of the inactive V1 candidate

Scope correction and experimental interpretation
Main reported that live GLM DCP4 uses VLLM_USE_V2_MODEL_RUNNER=true. The installed baseline source confirms that this is a V2 model runner despite the V1 engine/module namespace. The earlier candidates/mtp layer modifies vllm/v1/spec_decode/llm_base_proposer.py, which this native V2 MTP path does not call. That older directory is preserved without modification as an inactive V1 artifact. Its V2 serving arms cannot establish an MTP-constraint effect and must be labeled inactive-patch/control. This NEW directory layers only the two V2 files in manifest.json; no inactive V1 helper is included.

Evidence-backed active path
1. vllm/v1/worker/gpu/model_runner.py constructs the speculator via init_speculator, and calls speculator.propose with request temperature/seeds.
2. vllm/v1/worker/gpu/spec_decode/__init__.py chooses MTPSpeculator for method == 'mtp' (the separate Gemma4 branch remains separate).
3. MTPSpeculator inherits AutoRegressiveSpeculator. Its sample_draft invokes self._sample_probabilistic_draft when draft_logits is enabled.
4. The baseline shared DraftModelSpeculator._sample_probabilistic_draft calls native V2 gumbel_sample with apply_temperature=True and an output_processed_logits cache. Its _copy_request_inputs explicitly copies only temperature/seeds and ignores top-k/top-p.
5. Native gumbel_block_argmax stores processed logits before adding noise. It masks invalid request-state indices and rows beyond active_rows. Native rejection_sampler_utils reconstructs q using each cached draft logit minus its global logsumexp, including all--inf vocabulary tiles. Greedy temperature==0 takes a separate verification branch.

Changes
Only native MTPSpeculator receives the new probabilistic proposal override. The shared DraftModelSpeculator, AutoRegressiveSpeculator, other speculators, native Gumbel kernels, rejection kernels, and target sampler remain unchanged. The runner binds its final SamplingStates owner to MTPSpeculator immediately after sampler/custom-sampler initialization, before later warmup/capture.

The override gathers temperature/top-k/top-p in request-state order, including repeated/reordered row mappings. Invalid -1 rows gather a safe address and receive neutral constraints. Zero-temperature greedy rows also receive neutral top-k=vocabulary and top-p=1, retaining original argmax ties. Non-greedy logits are temperature-scaled in FP32, matching native Gumbel's existing promotion-before-division contract for FP32/BF16/FP16 heads. Requested top-k is bounded by the actual draft-logit vocabulary, so a target-vocabulary no-filter sentinel cannot index beyond the draft vocabulary. Existing apply_top_k_top_p supplies the same position-local filtering implementation used by native target constraint processing. History-dependent processors and min_p remain target-only; no defaults or MTP depth are changed.

Matching q and seeded state
The SAME filtered FP32 logits are passed to native gumbel_sample and stored in the existing draft_logits cache. apply_temperature=False avoids double scaling. The existing draft_gumbel_pos transform, per-request seeds, FP32/FP64 noise mode, scalar/per-row cache columns and active-row write guard are preserved. Native rejection therefore reconstructs the proposal q actually used for the draw. Unlike the inactive V1 helper, the active V2 path already has per-request/position-keyed seeded Gumbel sampling; this candidate retains that policy and does not consume a new global RNG stream or alter rejection RNG keys.

CUDA graph lifetime correction
Independent source review found that SamplingStates.top_k/top_p.gpu are NOT stable addresses: UvaBackedTensor.copy_to_uva rotates through UvaBufferPool and rebinds .gpu. Reading those views directly from a captured proposal would retain a stale pointer. The final candidate instead allocates two persistent device vectors when probabilistic draft_logits is enabled. MTPSpeculator._copy_request_inputs first runs the inherited temperature/seed/index copy, then copies the CURRENT UVA top-k/top-p views into those persistent vectors. AutoRegressiveSpeculator calls this copy before its prefill and decode graph replays. The captured helper gathers only the persistent vectors; no .item(), CPU synchronization, or host-data-dependent request branch is added inside replay. Greedy draft mode allocates no new filter vectors.
