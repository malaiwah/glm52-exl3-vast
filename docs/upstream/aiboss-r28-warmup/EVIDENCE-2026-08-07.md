## Corrected backend coverage

The first GPU version warmed only the maximum live row count in each power-of-two route-capacity bucket. A five-row request still JIT-compiled `_pack_topk_routes_small_prefix_kernel`: Triton also specializes the runtime `live_numel` scalar by alignment/divisibility class.

Commit `4404256` added the bucket maximum and first live member, covering aligned and non-aligned scalar classes. Native MTP then exposed a second missing dimension: target routes are `int32`, while the rank-sliced draft uses `int64`. Final commit `6022e6e` warms both route-ID dtypes and keys the prewarm cache by dtype. Focused exact-r28 tests pass 6/6; Ruff check and focused format checks are clean.

## Native MTP-draft closure

FP8 MLA KV allowed the checkpoint's native MTP1 draft to run on the 32 GB card. The target-only patch established the control: 58.8 tok/s CC1, 451 / 571 accepted draft tokens (79.0%), mean accepted length 1.790, and `FRUIT-MTP-OK`, but the rank-sliced draft lazily loaded the `small_prefix` and `sort` route-pack kernels.

The backend now prewarms rank-sliced full-rotation plans for every reachable capacity/scalar class, both `int32` and `int64` route IDs, and mapped/unmapped routes. Its cache signature includes route-ID dtype.

The exact final head initialized in 6.80 s with a populated compilation cache and still loaded no route-pack kernels after engine start. The isolated decode smokes (58.8 and 63.8 tok/s) are not treated as a throughput claim.

## AIBeast production corroboration

A read-only audit found that the untouched r28 production stack had already encountered this failure family while serving MTP3 at TP4/DCP4:

- 2026-08-07 10:11:29: TP3 called `_apply_mixed_rank_sliced` -> `run_mixed_trellis` -> `pack_topk_routes_by_expert` -> `_pack_topk_routes_post_prefix_kernel`.
- Triton's `load_binary()` failed with `RuntimeError: Triton Error [CUDA]: out of memory`.
- Scheduler telemetry showed two running requests and only 1.18% active KV usage, so active-request KV pressure was not the cause.
- The engine timed out and restarted; the new process later warned that `post_prefix` and `sort` were once again JIT-loading during inference.
- The restarted container was healthy when audited, with 355 MiB nominal free per GPU while fully loaded. Its current health does not remove the first-use hazard for any remaining unmaterialized rank/shape specialization.

The trace proves that late route-pack module residency can crash the production MTP stack. It does not identify that exact launch as target versus draft, so the implementation deliberately closes both owners.
