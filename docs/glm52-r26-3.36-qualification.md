## What the headline gain means

The upstream `+37.9/+38.2/+38.4%` result compares r26 against r25's **old
automatic DCP4 policy** on the 3.25-bpw/MTP0 release shape. Source inspection
confirms that r26 removes pure-overhead owner exchange and retains lossless
query/CKV transport. The direction and cause of that claim are sound.

The appliance had already forced owner merge off before r26. A matched
official-image A/B on 3.36-bpw/K6/MTP3 therefore measures the smaller remaining
gain from the complete r26 policy:

The second exact indexer shard costs some resident memory, but the automatic
pool remains 1.37 times the 524,288-token product requirement. Decode is not

query split on / full CKV gather 140,000 / two indexer shards / owner merge off

The turnkey entrypoint now lets r26's calibration helper resolve owner merge
and indexer-shard policy. Before this qualification it passed `owner=auto` but
silently retained the older hard-coded `indexer-shards=0`, bypassing part of
r26's speed policy. The profile also retains the measured 24 MiB lossless PCIe
DMA crossover instead of the older 6 MiB override. Maximum-context safety keeps
CKV prefetch depth zero: the probe measured a 3.3--4.1% overlap opportunity only
through 131K and did not qualify it for a 524K request.

Against the already-tuned r25 appliance result, r26 production PP is about
2.5--4.4% faster. The larger public gain does not compound with the owner-merge
optimization the appliance already carried. Synthetic decode used random
temperature-one continuations and had variable MTP acceptance; the soak under
real agent traffic is the authoritative production MAL/TG follow-up.

At idle the shape retained about 0.87--0.89 GiB/GPU. During the 522,359-token
request free memory bottomed near 0.4 GiB/GPU without an OOM. That reserve is
operational headroom, not spare capacity for DCP2 or FP8 KV. DCP2 would require
roughly another 5.52 GiB/GPU to preserve 524,288 global tokens. The already
qualified 656-byte FP8/BF16-RoPE record, versus the selected 368-byte dynamic
NVFP4/FP8-RoPE record, lost 18--21% PP and left only 81--93 MiB/GPU at its safe
512K shape.

The cold r26 cache namespace produced expected first-use CuTe/Triton compiles
after `/health`; all were persisted. A subsequent feature run recorded zero
post-ready compiles and zero XGrammar FSM, CUDA, distributed, process, or OOM
findings. Every API gate passed: ordinary and thinking chat, streaming usage,
multi-turn preserved thinking, structured JSON with and without thinking,
